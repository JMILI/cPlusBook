# 全局变量

## 一、全局变量的定义
在 C++ 里，变量除了能在函数内部声明，还能在函数外部声明，这类在函数外部声明的变量就被叫做全局变量。

## 二、全局变量的声明
按照编程惯例，全局变量通常在全局命名空间下，于文件顶部、`include` 语句的下方进行声明。以下为示例代码：
```cpp
#include <iostream>

// 函数外的变量是全局变量
int g_x {}; // 全局变量 g_x

void doSomething()
{
    // 全局变量声明后，可以在文件内的任意位置看到和使用
    g_x = 3;
    std::cout << g_x << '\n';
}

int main()
{
    doSomething();
    std::cout << g_x << '\n';

    // 全局变量声明后，可以在文件内的任意位置看到和使用
    g_x = 5;
    std::cout << g_x << '\n';

    return 0;
}
// 文件结束，g_x 离开作用域
```
上述代码的输出结果为：
```
3
3
5
```

## 三、全局变量的作用域
## （一）全局命名空间作用域
在全局命名空间中声明的标识符具有全局命名空间作用域，一般简称为全局作用域，有时也非正式地称作文件作用域。这表明这些标识符从声明点开始，一直到声明它们的文件末尾都是可见的。一旦全局变量声明完成，就能在文件的任意位置使用。就像在上述示例里，`doSomething()` 函数和 `main()` 函数都使用了全局变量 `g_x`。

## （二）用户定义命名空间中的全局变量
全局变量也能够在用户自定义的命名空间内定义。以下示例与前面的类似，不过 `g_x` 从全局范围移到了用户自定义的命名空间 `Foo` 中：
```cpp
#include <iostream>

namespace Foo // Foo 在全局命名空间中定义
{
    int g_x {}; // g_x 现在位于 Foo 命名空间中, 但仍是全局变量
}

void doSomething()
{
    // 全局变量声明后，可以在文件内的任意位置看到和使用
    Foo::g_x = 3;
    std::cout << Foo::g_x << '\n';
}

int main()
{
    doSomething();
    std::cout << Foo::g_x << '\n';

    // 全局变量声明后，可以在文件内的任意位置看到和使用
    Foo::g_x = 5;
    std::cout << Foo::g_x << '\n';

    return 0;
}
```
尽管标识符 `g_x` 现在被限制在命名空间 `Foo` 内，但通过 `Foo::g_x` 仍可全局访问它，所以 `g_x` 依旧属于全局变量。由此我们可以得出一个关键点：在命名空间内声明的变量同样是全局变量。

## 四、全局变量的存储期
全局变量具有静态存储期，这意味着它们在程序启动时就会被创建，直到程序结束才会被销毁。具有静态存储期的变量有时也被叫做静态变量。

## 五、全局变量的命名
## （一）前缀的使用
按照编程习惯，部分开发者会在非常量的全局变量标识符前面加上“g”或者“g_”，其目的在于表明这些变量是全局的。该前缀主要有以下几种用途：
1. 避免与全局命名空间中的其他标识符发生命名冲突。
2. 防止无意中出现的命名遮挡（后续会详细探讨）。
3. 提示变量存在于函数范围之外，对它们所做的任何更改都会持续保留。

## （二）命名空间内全局变量的命名
在用户自定义的命名空间内定义的全局变量通常会省略这个前缀。这是因为在这种情况下，前面提到的前两个问题一般不会出现，而且当我们看到命名空间名称时，就能推断出变量是全局的。

**最佳实践**：在为非常量的全局变量命名时，建议考虑使用“g”或“g_”前缀，以便将它们和局部变量、函数参数区分开来。

## 六、全局变量的初始化
## （一）默认初始化
与局部变量（默认情况下未初始化）不同，具有静态存储期的全局变量默认会被零初始化。

## （二）显式初始化
我们也可以选择对非常量的全局变量进行显式初始化，示例如下：
```cpp
int g_x;       // 未显式初始化 (默认被初始化为 0)
int g_y {};    // 值初始化 (被初始化为 0)
int g_z { 1 }; // 使用特定的值，进行列表初始化
```

## 七、常量全局变量
和局部变量一样，全局变量也可以是常量。但和所有常量一样，常量全局变量必须进行初始化。示例代码如下：
```cpp
#include <iostream>

const int g_x;     // 错误: const 变量必须初始化
constexpr int g_w; // 错误: constexpr 变量必须初始化

const int g_y { 1 };     // const 全局变量 g_y, 使用 1 初始化
constexpr int g_z { 2 }; // constexpr 全局变量 g_z, 使用 2 初始化

void doSomething()
{
    // 全局变量声明后，可以在文件内的任意位置看到和使用
    std::cout << g_y << '\n';
    std::cout << g_z << '\n';
}

int main()
{
    doSomething();

    // 全局变量声明后，可以在文件内的任意位置看到和使用
    std::cout << g_y << '\n';
    std::cout << g_z << '\n';

    return 0;
}
// g_y g_z 离开作用域
```

## 八、关于（非常量）全局变量的使用建议
新手程序员常常倾向于使用大量的全局变量，原因在于使用全局变量时，无需将它们显式地传递给每个需要使用它们的函数。然而，在实际编程中，通常应尽量避免使用非常量的全局变量。

## 九、快速摘要
## （一）非常量全局变量
```cpp
int g_x;                 // 定义一个未显式初始化的全局变量 (默认初始化为 0)
int g_x {};              // 定义一个显式初始化为 0 的全局变量
int g_x { 1 };           // 定义一个显式初始化为 1 的全局变量
```

## （二）Const 全局变量
```cpp
const int g_y;           // 错误: const 变量必须初始化
const int g_y { 2 };     // 定义一个使用 2 初始化的 const 全局变量
```

## （三）Constexpr 全局变量
```cpp
constexpr int g_y;       // 错误: constexpr 变量必须初始化
constexpr int g_y { 3 }; // 定义一个使用 3 初始化的全局 constexpr 变量
```

## 为什么（非常量）全局变量是邪恶的？

全局变量是编程中一个常见但容易被滥用的概念。尽管它们在小型项目中可能看起来无害，但在大型项目中，非常量全局变量往往会引发许多问题。以下是详细的原因和解决方案。

---

### **1. 全局变量的主要问题**

#### **1.1 不可预测的程序状态**
全局变量可以在程序的任何地方被修改，导致程序状态难以预测。

**示例代码：**
```cpp
#include <iostream>

int g_mode; // 全局变量

void doSomething() {
    g_mode = 2; // 修改全局变量
}

int main() {
    g_mode = 1; // 设置全局变量
    doSomething();

    if (g_mode == 1) {
        std::cout << "No threat detected.\n";
    } else {
        std::cout << "Launching nuclear missiles...\n";
    }
}
```
**问题**：
- `doSomething()` 修改了 `g_mode`，但 `main()` 中的代码并不知道这一点。
- 程序的行为变得不可预测，增加了调试和维护的难度。

---

#### **1.2 调试困难**
全局变量可以在程序的任何地方被修改，导致调试时需要检查整个代码库。

**示例场景**：
- 假设 `g_mode` 的值被错误地设置为 `3`，而预期值是 `4`。
- 为了找到问题，必须检查所有可能修改 `g_mode` 的代码。

---

#### **1.3 降低模块化**
全局变量破坏了函数的独立性，使函数依赖于外部状态，降低了代码的模块化和可重用性。

**示例代码：**
```cpp
void someFunction() {
    if (g_mode == 4) {
        // 执行某些操作
    }
}
```
**问题**：
- `someFunction()` 的行为依赖于全局变量 `g_mode`，无法独立测试和理解。

---

#### **1.4 初始化顺序问题**
全局变量的初始化顺序在 C++ 中是未定义的，尤其是在多个文件中。

**示例代码：**
```cpp
#include <iostream>

int initX(); // 前向声明
int initY(); // 前向声明

int g_x{ initX() }; // g_x 先初始化
int g_y{ initY() };

int initX() {
    return g_y; // g_y 尚未初始化
}

int initY() {
    return 5;
}

int main() {
    std::cout << g_x << ' ' << g_y << '\n'; // 输出 0 5
}
```
**问题**：
- `g_x` 依赖于 `g_y`，但 `g_y` 尚未初始化，导致 `g_x` 的值为 `0`。

---

### **2. 全局变量的替代方案**

#### **2.1 使用局部变量**
尽可能使用局部变量，将数据通过函数参数传递。

**示例代码：**
```cpp
void doSomething(int mode) {
    // 使用局部变量
    if (mode == 2) {
        // 执行某些操作
    }
}
```

---

#### **2.2 封装全局变量**
将全局变量封装在命名空间或类中，并提供访问函数。

**示例代码：**
```cpp
namespace Constants {
    constexpr double gravity{ 9.8 };
}

double getGravity() {
    return Constants::gravity;
}
```

---

#### **2.3 使用单例模式**
对于需要在全局范围内共享的数据，可以使用单例模式。

**示例代码：**
```cpp
class Logger {
public:
    static Logger& getInstance() {
        static Logger instance;
        return instance;
    }

    void log(const std::string& message) {
        std::cout << message << '\n';
    }

private:
    Logger() {} // 私有构造函数
};
```

---

### **3. 全局变量的合理使用场景**

尽管非常量全局变量通常不推荐使用，但在某些情况下，它们可能是合理的：

- **日志系统**：全局日志对象可以在程序的任何地方使用。
- **配置参数**：全局配置参数可以在程序启动时初始化，并在整个程序中使用。

**示例代码：**
```cpp
namespace Config {
    extern int maxConnections; // 全局配置参数
}
```

---

### **4. 保护自己免受全局变量的破坏**

如果必须使用全局变量，可以采取以下措施减少风险：

#### **4.1 使用命名空间**
将全局变量放入命名空间，避免命名冲突。

**示例代码：**
```cpp
namespace Constants {
    constexpr double gravity{ 9.8 };
}
```

#### **4.2 封装访问**
通过函数访问全局变量，而不是直接使用。

**示例代码：**
```cpp
namespace Constants {
    constexpr double gravity{ 9.8 };
}

double getGravity() {
    return Constants::gravity;
}
```

#### **4.3 避免直接依赖**
在函数中使用参数传递数据，而不是直接依赖全局变量。

**示例代码：**
```cpp
double instantVelocity(int time, double gravity) {
    return gravity * time;
}
```

---

### **5. 总结**

| 全局变量的主要问题 | 解决方案                     |
|-----------|------------------------------|
| 不可预测的程序状态 | 使用局部变量                 |
| 调试困难      | 封装全局变量                 |
| 降低模块化     | 使用函数参数传递数据         |
| 初始化顺序问题   | 避免动态初始化               |

**最佳实践**：
- 尽量避免使用非常量全局变量。
- 使用局部变量、命名空间和封装技术来替代全局变量。
- 如果必须使用全局变量，确保其使用范围最小化，并通过函数访问。
