# 局部变量
在程序设计的领域中，变量是存储数据的基本单元，而局部变量作为其中的一种重要类型，有着独特的性质和使用规则。

## 一、局部变量的定义与作用域
局部变量是在函数内部定义的变量，其中函数参数也被视作特殊的局部变量。这一定义方式将其作用范围严格限制在函数体内部。从更专业的角度来讲，局部变量具有代码块作用域，即从它的定义点开始，一直到包含该定义的代码块结束，这个变量都处于有效的作用域内。例如：
```cpp
int main() {
    int num1 = 10;  // num1进入作用域
    double num2 = 20.5;  // num2进入作用域

    // 在这里可以使用num1和num2
    return 0;
}  // num1和num2离开作用域
```
值得注意的是，虽然函数参数并非在函数体内部使用常规的变量定义方式声明，但在作用域的概念里，它们被当作函数体内作用域的一部分。比如在下面这个求最大值的函数中：
```cpp
int max(int a, int b) {  // a和b进入作用域
    int result = (a > b)? a : b;  // result进入作用域
    return result;
}  // result、b、a离开作用域
```
在同一作用域内，所有变量的名称必须是唯一的。这是一条非常重要的规则，违反它会导致编译错误。例如：
```cpp
void testFunction(int param) {
    int param = 0;  // 编译失败，param与参数名称冲突
}

int main() {
    return 0;
}
```
在上述代码中，`testFunction`函数体内定义的变量`param`与函数参数`param`同名，且都处于相同的块作用域，因此无法通过编译。

## 二、局部变量的存储期
变量的存储期决定了它何时被创建以及何时被销毁，而局部变量具有自动存储期。这意味着当程序执行到局部变量的定义点时，该变量被创建并分配内存空间；当程序执行到定义它的代码块末尾时，变量被销毁，其所占用的内存空间被释放。例如：
```cpp
int main() {
    int localVar = 5;  // localVar创建与初始化
    double anotherVar = 3.14;  // anotherVar创建与初始化

    // 变量使用逻辑
    return 0;
}  // anotherVar、localVar在这里被销毁
```
由于这种自动创建和销毁的特性，局部变量也常被称为自动变量。

## 三、嵌套代码块中的局部变量
局部变量不仅可以在函数体的主代码块中定义，还可以在嵌套的代码块中定义。在嵌套代码块中定义的局部变量，其作用域和生命周期同样遵循从定义点到代码块末尾的规则。例如：
```cpp
int main() {  // 外围代码块
    int outerVar = 10;  // outerVar进入作用域，并被创建

    {  // 内层代码块
        int innerVar = 20;  // innerVar进入作用域，并被创建
    }  // innerVar离开作用域，并被销毁

    // 此时innerVar无法再被使用，因为它已离开了作用域

    return 0;
}  // outerVar离开作用域，并被销毁
```
这里需要特别指出的是，嵌套块被视为定义它的外部块作用域的一部分。因此，在嵌套块内可以访问外部块中定义的变量。例如：
```cpp
#include <iostream>

int main() {
    int outer = 5;  // outer进入作用域，并被创建

    {
        int inner = 7;  // inner进入作用域，并被创建

        // outer与inner都在作用域中
        std::cout << outer << " + " << inner << " = " << outer + inner << '\n';
    }  // inner离开作用域，并被销毁

    // inner无法再被使用，因为离开了作用域

    return 0;
}  // outer离开作用域，并被销毁
```

## 四、局部变量的链接属性
标识符具有链接属性，它决定了同一名称的不同声明是否引用同一个对象。而局部变量的一个重要特点是没有链接属性，这就表明每个局部变量的声明都是一个独立的、唯一的对象。例如：
```cpp
int main() {
    int var1 = 2;  // 局部变量 无链接

    {
        int var1 = 3;  // 这里的var1，与外围的var1，不是同一个对象
    }

    return 0;
}
```
虽然作用域和链接性在概念上有一定的相似性，但它们有着本质的区别。作用域定义的是单个声明在代码中可见和可使用的位置，而链接性定义的是多个声明是否引用同一个对象。在局部变量的情境下，链接性的概念可能不太容易直接体现出其价值，但在后续更深入的学习中，它会发挥重要的作用。

## 五、变量定义的最佳实践
在编写程序时，遵循“在最有限的现有作用域内定义变量”这一最佳实践原则是非常重要的。如果一个变量仅在某个嵌套块中被使用，那么就应该在这个嵌套块中进行定义。例如：
```cpp
#include <iostream>

int main() {
    // 不要在这里定义temp
    {
        // temp只在这个代码块内使用，所以在这里定义
        int temp = 5;
        std::cout << temp << '\n';
    }
    // 后续不再使用temp，所以没有必要在外部作用域看到它的定义

    return 0;
}
```
这样做有诸多好处，一方面可以减少程序的复杂性，因为同时处于可访问状态的变量数量减少了；另一方面，也更容易查看变量在何处被使用（或未被使用），从而使程序的逻辑更加清晰易懂。

然而，如果在外部块中也需要使用某个变量，那么就必须在外部块中进行声明。例如：
```cpp
#include <iostream>

int main() {
    int count = 5;  // 在这里定义count，因为在外围的代码块中需要使用它

    {
        int input;
        std::cin >> input;

        // 如果在count的第一次使用之前定义在内部块，在外围块中将无法访问到它
        if (input == 4)
            count = 4;
    }

    std::cout << count;  // 需要在这里能访问到count

    return 0;
}
```
有些新手开发人员可能会考虑为了特意限制变量的作用域（并强制它提前超出作用域/销毁）而创建嵌套块。虽然这样做在一定程度上可以使变量的逻辑更加简单，但往往会导致整个函数变得更长、更复杂。在大多数情况下，这种折衷是不值得的。如果创建嵌套块的目的仅仅是为了限制变量作用域，那么将这部分代码放在一个单独的函数中会是更好的选择。
