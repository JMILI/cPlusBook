# 内部链接

## 一、内部链接概述
在之前关于局部变量的介绍中，我们了解到“标识符的链接属性决定了该名称的其他声明是否引用同一对象”，并且局部变量没有链接属性。而全局变量和函数标识符具有内部链接或外部链接属性。本节课我们将聚焦于内部链接，外部链接会在下一节详细介绍。

具有内部链接的标识符，只能在单个翻译单元内被看到和使用，不会向链接器公开，也就意味着无法从其他翻译单元访问。这就导致，如果两个源文件中存在同名且具有内部链接的标识符，它们会被视为独立的，不会因重复定义而引发单一定义规则（ODR）冲突。

## 二、具有内部链接的全局变量
具有内部链接的全局变量也被称作内部变量。对于非常量的全局变量，若要使其成为内部变量，可使用 `static` 关键字。示例代码如下：
```cpp
#include <iostream>

static int g_x{}; // 非常量的全局变量默认是外部链接，通过 static 关键字使其成为内部链接
const int g_y{ 1 }; // const 全局变量默认是内部链接
constexpr int g_z{ 2 }; // constexpr 全局变量默认是内部链接

int main()
{
    std::cout << g_x << ' ' << g_y << ' ' << g_z << '\n';
    return 0;
}
```
默认情况下，`const` 和 `constexpr` 全局变量本身就具备内部链接属性，所以不需要使用 `static` 关键字，即便使用也不会产生额外效果。

下面是一个涉及多个文件使用内部变量的例子：
- **a.cpp**
```cpp
constexpr int g_x { 2 }; // 此内部链接的 g_x 仅在 a.cpp 中可访问
```
- **main.cpp**
```cpp
#include <iostream>

static int g_x { 3 }; // 此内部链接的 g_x 仅在 main.cpp 中可访问

int main()
{
    std::cout << g_x << '\n'; // 使用 main.cpp 中的 g_x，打印 3
    return 0;
}
```
该程序的输出为：
```
3
```
由于 `g_x` 是每个文件的内部变量，`main.cpp` 并不知道 `a.cpp` 中也存在名为 `g_x` 的变量，反之亦然。

对于有更高编程水平追求的读者，需要知道上述 `static` 关键字的使用属于存储类说明符（storage class specifier）的一种情况，它能够设置名称的链接属性和存储期。常见的存储类说明符有 `static`、`extern` 和 `mutable`。

## 三、具有内部链接的函数
链接是标识符的属性，并非变量所独有，函数标识符同样具有链接属性。函数默认是外部链接（后续课程会详细讲解），不过可以使用 `static` 关键字将其设置为内部链接。示例如下：
- **add.cpp**
```cpp
// 此函数被声明为 static，只能在本文件中使用
// 即便其他文件有 add 函数的前向声明，也无法访问该函数
static int add(int x, int y)
{
    return x + y;
}
```
- **main.cpp**
```cpp
#include <iostream>

static int add(int x, int y); // 前向声明 add

int main()
{
    std::cout << add(3, 4) << '\n';
    return 0;
}
```
这个程序无法成功链接，原因是在 `add.cpp` 之外无法访问 `add` 函数。

## 四、单定义规则和内部链接
依据单定义规则，对象或函数在文件或程序中不能有多个定义。但不同文件中定义的内部对象（和函数），即便名称和类型相同，也会被视为独立的实体，不会违反单定义规则，因为每个文件中的内部对象都只有一个定义。

## 五、`static` 与未命名的命名空间对比
在现代 C++ 编程里，使用 `static` 关键字为标识符提供内部链接的做法逐渐不受青睐。未命名的命名空间能为更广泛的标识符（如类型标识符）提供内部链接，并且更适合为多个标识符设置内部链接。后续课程会详细探讨未命名的命名空间。

## 六、为标识符提供内部链接的原因
让标识符具有内部链接通常基于以下两个原因：
1. **限制访问**：对于某些不希望被其他文件访问的标识符，比如不想被随意修改的全局变量，或者不希望被调用的辅助函数，赋予其内部链接属性可以确保安全性。
2. **避免命名冲突**：由于具有内部链接的标识符不会向链接器公开，所以它们只会与同一翻译单元内的名称产生冲突，而不会在整个程序中引发命名冲突。

许多现代开发指南建议，将不打算在其他文件中访问的变量或函数都设置为内部链接。如果能完全遵循这一建议，是非常不错的做法。当然，更灵活的准则是，将有明确理由不允许从其他文件访问的标识符设置为内部链接。

## 七、最佳实践
当有明确理由不允许其他文件访问某个标识符时，应将其设置为内部链接。最好使用未命名的命名空间，将所有不希望被其他文件访问的标识符都设置为内部链接。

## 八、快速摘要
```cpp
// 全局变量 内部链接 定义:
static int g_x;          // 定义未初始化的 内部全局变量 (默认初始化为0)
static int g_x{ 1 };     // 定义初始化了的 内部全局变量

const int g_y { 2 };     // 定义初始化了的 const 内部全局变量
constexpr int g_y { 3 }; // 定义初始化了的 constexpr 内部全局变量

// 函数 内部链接 定义:
static int foo() {};     // 定义 内部 函数
```
