# 要点总结

### 1.常量

- **常变量**是C++中最常见的命名常量类型，使用`const`关键字声明。
- **类对象宏**不推荐使用，因为它们不遵循作用域规则且难以调试。
- **const函数参数**和**常量返回值**在大多数情况下不推荐使用。
- **类型限定符**`const`和`volatile`用于修改类型的行为。

### 2.常量表达式，编译时常量，运行时常量

- **常量表达式**和**编译时常量**有助于编译器进行优化，减少运行时开销。
- **运行时常量**用于确保对象的值在运行时不会被修改，但无法在编译时优化。
- 使用 `const` 关键字可以帮助编译器更好地优化代码，尤其是在使用编译时常量时。

### 3. constexpr和const

| 概念                | 说明                                                                 |
|---------------------|----------------------------------------------------------------------|
| **`constexpr` 变量** | 必须用常量表达式初始化，确保编译时求值，优化确定性高。               |
| **`const` 变量**     | 可为编译时或运行时常量，初始化灵活性高，优化依赖上下文。             |
| **常量折叠**         | 编译器优化策略，将常量子表达式替换为结果值，即使上下文为运行时。     |
| **函数参数**         | 不可用 `constexpr`，函数内视为运行时常量。                           |

通过 `constexpr` 明确编译时常量意图，帮助编译器优化代码，提升性能。


### 4. 字面值常量（字面量）和魔数

在代码中避免使用魔数（改用 `constexpr` 变量）。

### 6. 内联函数和内联变量

- **内联函数**：通过消除函数调用开销提升性能，适合简单、短小的函数。
- **`inline` 关键字**：现代 C++ 中主要用于允许多个编译单元中定义相同的函数或变量。
- **编译器优化**：现代编译器自动决定是否内联，开发者应避免手动干预。

### 7. `constexpr` 和 `consteval` 函数

- `constexpr` 函数返回值可在编译时计算，也可在运行时求值，仅在需要常量表达式处使用返回值才保证编译时求值。
- `consteval` 函数（C++20）必须在编译时求值，否则编译错误，可辅助 `constexpr` 函数编译时执行。
- `constexpr` 和 `consteval` 函数隐式内联，参数不是 `constexpr`，但可作为其他 `constexpr` 函数参数。
- `constexpr` 函数在非常量上下文可调用非常量表达式函数，建议避免并使用 `std::is_constant_evaluated()` 区分行为，测试用常量上下文。 

### 8. c样式字符串，std::string,std::string_view

**特性对比**：

| 特性                  | C 样式字符串          | std::string              |
|-----------------------|-----------------------|--------------------------|
| 内存管理              | 手动                  | 自动                     |
| 长度调整              | 固定长度              | 动态扩展                 |
| 赋值操作              | `strcpy` 风险         | 直接 `=` 安全赋值        |
| 输入处理              | 无安全方法            | `std::getline` + `std::ws` |
| 函数参数传递          | 必须按指针            | 按引用避免拷贝           |
| 常量表达式支持        | 支持                  | C++20 有限支持           |

**类型转换规则**： string_view作为形参能接收不同类型

| 源类型          | 目标类型         | 是否隐式转换 |
|-----------------|------------------|--------------|
| C 样式字符串    | std::string_view | 是           |
| std::string     | std::string_view | 是           |
| std::string_view| std::string      | 否           |

 **性能对比与选择指南**：

| 特性                | std::string          | std::string_view     |
|---------------------|----------------------|----------------------|
| 内存管理            | 拥有数据             | 视图引用             |
| 修改能力            | 支持修改             | 只读                 |
| 复制成本            | 高（深拷贝）         | 低（复制指针）       |
| 适用场景            | 需要修改的字符串     | 只读访问             |
| 生命周期            | 独立管理             | 依赖原字符串         |
| constexpr 支持      | 有限支持             | 完全支持             |

 **返回值优化（RVO）**
```cpp
// 安全返回局部对象（编译器优化避免拷贝）
std::string createName() {
    std::string local = "Temporary";
    return local; // 触发移动语义（C++11+）
}
```
**选择建议**：
1. 需要修改字符串内容 → `std::string`
2. 只读访问，特别是函数参数 → `std::string_view`
3. 编译期字符串处理 → `constexpr std::string_view`

 关键选择标准表

| 场景                      | 推荐类型         | 理由                      |
|---------------------------|------------------|---------------------------|
| 函数只读参数              | string_view      | 避免拷贝，支持多种输入    |
| 需要修改字符串内容        | string           | 唯一可变类型              |
| 处理用户输入              | string           | 保证数据所有权            |
| 编译期常量字符串          | string_view      | 支持constexpr             |
| 临时子字符串处理          | string_view      | 零拷贝高效                |
| 需要保证空终止符          | string           | 确保字符串完整性          |
