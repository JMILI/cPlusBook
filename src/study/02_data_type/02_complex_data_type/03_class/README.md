# 要点总结

### 01.面向对象编程简介

| 特性                    | 面向过程编程                 | 面向对象编程                  |
|-------------------------|-----------------------------|------------------------------|
| **数据和行为的关系**      | 数据和行为分离               | 数据和行为结合在对象中         |
| **代码组织**              | 通过函数组织                 | 通过类和对象组织               |
| **可扩展性**              | 添加新功能时可能需要修改多个地方 | 添加新功能时，修改较少，扩展更容易 |
| **维护性**                | 随着程序复杂度增加，修改更困难 | 随着程序复杂度增加，模块化和扩展性较好 |

面向对象编程带来了许多好处：

- **模块化**：OOP允许将不同的功能封装在类中，类的实例可以作为对象使用，减少了代码的冗余。
- **数据封装**：数据和操作数据的方法封装在一起，数据的访问受控，增加了数据的安全性。
- **继承**：OOP允许类继承其他类的特性，代码重用性高，子类可以继承父类的属性和方法，并且可以在子类中进行扩展。
- **多态**：通过多态机制，可以在不改变调用代码的情况下，动态地选择适当的方法。

### 02.class简介

| 特性            | 结构体（struct）                         | 类（class）                   |
|-----------------|----------------------------------------|------------------------------|
| **默认访问权限** | 公有（public）                          | 私有（private）               |
| **成员函数**    | 支持，但通常不使用                       | 支持，通常用于操作类的成员    |
| **数据封装**    | 不强制封装，所有成员通常是公有的        | 强制封装，成员默认是私有的    |
| **面向对象支持** | 支持，但一般用于存储数据                | 完全支持面向对象特性，包括封装、继承和多态 |

### 03.成员函数

- **成员函数** 是类或结构体的一部分，它可以直接访问类或结构体中的成员。
- 成员函数在调用时，隐式传递**当前对象作为参数**，访问成员变量时无需显式指定对象。
- **成员函数重载** 允许同一个函数名根据不同的参数定义多个版本。
- **没有数据成员的类** 主要用于功能性组织，可以用命名空间代替。

### 04.Const类对象和Const成员函数

| **关键点**                         | **描述**                                                       |
|-------------------------------------|---------------------------------------------------------------|
| **Const 类对象**                    | `const` 修饰的类对象在初始化后不能修改其数据成员。                       |
| **Const 成员函数**                  | 被标记为 `const` 的成员函数保证不修改对象的任何成员，可以在 `const` 对象上调用。 |
| **非 Const 成员函数**                | `const` 对象不能调用非 `const` 成员函数，因为它们可能修改对象状态。      |
| **通过常量引用传递对象**            | 通过常量引用传递对象可以避免对象副本，并确保对象在函数内部不会被修改。   |
| **成员函数重载**                    | 可以为同一个函数提供 `const` 和非 `const` 的重载版本，根据对象类型来调用。|

常量成员函数：只能被 const 对象调用。当使用 const 对象调用成员函数时，编译器会优先选择常量成员函数。
void print() const{}

### 05.公共和私有成员以及访问说明符

| 访问级别 | 访问说明符 | 类外部可访问 | 类内部可访问 | 子类可访问 |
|-----------|------------|--------------|--------------|------------|
| 公共      | `public`   | 是           | 是           | 是         |
| 受保护    | `protected`| 否           | 是           | 是         |
| 私有      | `private`  | 否           | 是           | 否         |


### 06.访问函数

1. **需要在外部访问对象的某个成员时：** 如果某个私有成员需要在外部访问或修改，并且没有涉及复杂的约束或操作，使用访问函数是合理的。
2. **需要对成员访问进行校验或处理时：** 比如某个成员的值需要限制在某个范围内，或者修改时需要执行其他逻辑，setter 函数就显得非常有用。
3. **结构体类型的数据封装：** 对于简单的数据结构，可能不需要访问函数，直接公开成员变量更为简单。

### 07.成员函数返回对数据成员的引用

- 按值返回基本类型数据和按引用返回大规模数据
- 返回常量引用：数据只读
- 使用auto自动推导返回类型
- 返回右值引用：可能会导致未定义行为，需要谨慎使用
- 不要返回私有数据的非常量引用：T&,数据可能会被修改
- 常量成员函数不能返回非常量引用


### 08.数据隐藏（封装）的好处

- 降低复杂性
- 维护不变量
- 错误检测和处理
- 实现细节的修改不影响外部使用
- 更容易调试



### 09.构造函数简介


- **构造函数应该初始化对象的所有成员**，并且提供默认构造函数以确保对象在创建时是有效的。
- **Setter 方法**：如果需要修改对象的部分成员，可以使用 setter 方法。在设置新值时可以考虑添加校验逻辑来确保数据一致性。
- **构造函数**：在对象创建时被调用，负责初始化对象。
- **析构函数**：在对象销毁时被调用，负责清理资源，如释放内存、关闭文件等。
- 构造函数不能是 `const`

### 10.构造函数成员初始化列表

- 成员初始化列表:
```cpp
Foo(int x, int y)
    : m_x { x }
    , m_y { y }
{
}
```
- 确保在成员初始化列表中，成员的顺序与它们在类中定义的顺序一致
- 默认成员初始值设定项与初始化列表:
  1. 如果成员在初始化列表中列出，则使用初始化列表中的值。
  2. 如果成员没有在初始化列表中列出，但它有默认值，则使用类内的默认值。
  3. 如果成员没有默认值且没有在初始化列表中初始化，将导致编译错误。
- 构造函数的主体通常用于执行一些额外的操作，如打印日志、打开文件或执行资源分配等


### 11.默认构造函数和默认参数

- 优先使用显式默认构造函数（`=default`）而不是定义一个空构造函数。
- 默认构造函数应该只有在必要时才使用，特别是当类类型的默认初始化具有意义时。
- 使用默认构造函数时，确保类成员变量有合理的默认值，避免未初始化的成员变量导致未定义行为。
- 构造函数的重载使得可以根据传递的参数选择不同的构造函数

### 12.委托构造函数

- **委托构造函数**允许一个构造函数将初始化任务委托给同一类中的另一个构造函数。这样可以避免冗余代码，
- 委托构造函数的限制:
  1. **不能同时进行委托和初始化：** 构造函数要么是委托给其他构造函数，要么是自己初始化成员变量，不能同时做这两件事。
  2. **避免无限递归：** 如果两个构造函数互相委托，将形成无限递归，最终会导致堆栈溢出错误。因此，需要确保每个构造函数最终能够解析为非委托构造函数。
- - **使用命名常量：** 在多个构造函数中使用相同的默认值时，考虑使用`constexpr`或其他命名常量，避免硬编码的初始化值，从而提升代码的可维护性。


### 13.临时类对象

- 临时对象是没有名字的对象，在表达式结束后自动销毁。
- 临时对象的**生命周期**通常由其所在的完整表达式决定
- 临时对象本质上是右值
- C++的返回值优化（RVO）和命名返回值优化（NRVO）常常可以消除临时对象的创建

### 14.拷贝构造函数简介

##### 1. 拷贝构造函数概述
- **定义**：用于使用相同类型的现有对象来初始化新对象，执行后新对象是传入对象的副本。
- **隐式拷贝构造函数**：若未为类提供拷贝构造函数，C++会创建public隐式拷贝构造函数，默认执行成员级初始化。

##### 2. 自定义拷贝构造函数
- **定义方式**：参数通常为常量左值引用，以避免修改传入对象。例如`Fraction(const Fraction& fraction)`。
- **最佳实践**：除复制对象外不应有其他副作用，优先使用隐式拷贝构造函数，除非有特定需求。

##### 3. 拷贝构造函数的调用场景
- **对象初始化**：如`Fraction fCopy { f };`使用已有对象`f`初始化`fCopy`时调用。
- **按值传递和返回对象**：对象按值传递给函数或从函数按值返回时，会隐式调用拷贝构造函数进行复制。

##### 4. 特殊语法
- **= default**：显式请求编译器创建默认的拷贝构造函数，如`Fraction(const Fraction& fraction) = default;`。
- **= delete**：将拷贝构造函数标记为deleted，防止类的对象被复制，如`Fraction(const Fraction& fraction) = delete;`。

##### 5. 相关原则
- **三/五法则**：如果类需要用户定义的拷贝构造函数、析构函数或拷贝赋值运算符，那么可能需要所有这三个；在C++11中，还应考虑移动构造函数和移动赋值运算符。不遵循此原则可能导致代码故障。


### 15.类初始化和拷贝省略

##### 1.类初始化的基本类型


| 初始化方式                 | 描述                          | 示例代码               |
|------------------------|-----------------------------|---------------------|
| 默认初始化               | 无初始值，使用默认构造函数创建对象 | `int a;`             |
| 拷贝初始化               | 使用等号赋值初始化对象，拷贝构造函数被调用 | `int b = 5;`         |
| 直接初始化               | 使用括号初始化，调用匹配的构造函数   | `int c(6);`          |
| 直接列表初始化 (C++11)    | 使用大括号初始化，优先使用列表构造函数 | `int d{7};`          |
| 拷贝列表初始化           | 等号后跟大括号初始化            | `int e = {8};`       |
| 值初始化                 | 使用空大括号进行值初始化，调用默认构造函数  | `int f{};`           |


1. **列表初始化不允许窄化转换**  
2. **拷贝初始化仅考虑非`explicit`构造函数**  
3. **列表初始化优先匹配列表构造函数**

##### 2.拷贝省略定义

- 拷贝省略是一种编译器优化技术，它允许编译器消除不必要的拷贝操作。即使在程序中存在明显的拷贝构造函数调用，编译器也可以将其省略，以提高性能。拷贝省略发生在以下两种情况：
- **传值返回**：当函数返回一个对象时，通常会调用拷贝构造函数来复制该对象。但编译器可以优化此操作，直接返回该对象，避免拷贝构造。
- **传值参数**：当函数接受一个对象的值参数时，编译器也可能优化掉拷贝构造函数的调用。

### 16.转换构造函数和explicit关键字

| 关键概念           | 说明                                       |
|----------------|------------------------------------------|
| 转换构造函数         | 构造函数用于将一种类型的值转换为另一种类型的对象。                |
| `explicit` 关键字 | 防止构造函数参与隐式类型转换，确保转换只发生在显式初始化时。           |
| 隐式转换的副作用       | 隐式转换可能会导致意外行为，使用 `explicit` 可以减少这种问题的发生。 |
| 直接初始化和列表初始化    | 即使构造函数是 `explicit`，仍然可以在直接初始化和列表初始化中使用它。 |


### 17.隐藏的“this”指针和成员函数调用

| 关键点                 | 说明 |
|---------------------|------|
| `this` 是指针而不是引用   | `this` 指针指向当前对象，它是一个常量指针。 |
| `this` 用于访问成员       | 可以显式或隐式地使用 `this` 来访问当前对象的成员。 |
| `this` 使得成员函数能访问调用对象 | 通过 `this`，成员函数可以获取调用它的对象的地址。 |
| `this` 在链式调用中应用     | 可以通过返回 `*this` 来实现函数链式调用。 |
| `this` 和常量对象        | 对于 `const` 成员函数，`this` 指向常量对象，不能修改对象。 |


```cpp
static void setID(Simple* const this, int id) { this->m_id = id; }
```

### 18.类和头文件

- **类的声明**放在头文件中，**成员函数的实现**放在源文件中。这样可以提高代码的可读性和可维护性。
- 使用**内联函数**来避免函数调用的开销。对于简短的成员函数，可以直接放在类定义中实现，编译器会自动将其内联。
- **头文件保护**是非常重要的，使用 `#ifndef` 或 `#pragma once` 来防止多重包含。
- **默认参数**应放在类定义中。
- 在实际项目中，为了减少编译依赖和提高重用性，通常会将类分离成 `.h` 和 `.cpp` 文件。

### 19.嵌套类型（成员类型）

- **嵌套类型**是一种强大的工具，可以将类型封装在类内部，减少全局命名空间的污染，并增强代码的可读性和结构性。
- **枚举、类型别名和嵌套类**都是常见的嵌套类型，它们使得类更具模块化和可维护性。
- 使用嵌套类型时，注意**访问规则**、**命名空间管理**和**前向声明限制**，以便编写高效且可扩展的代码。

### 20.析构函数简介

- **自动调用**：析构函数在对象销毁时自动调用。
- **资源清理**：用于释放对象在生命周期中分配的资源，如内存、文件句柄等。
- **避免手动调用**：通常不需要显式调用析构函数，编译器会自动处理。
- **异常处理与RAII**：异常发生时，确保资源释放可以通过 RAII 原则来避免资源泄漏。
- `std::exit()` 函数可以立即终止程序。当调用 `std::exit()` 时，局部变量不会被销毁，因此不会调用析构函数。如果依赖析构函数来执行清理操作，应该小心使用 `std::exit()`，以避免资源泄漏。

### 21.具有成员函数的类模板

| 特性                 | 描述                                                         |
|----------------------|--------------------------------------------------------------|
| **模板参数**         | 类模板和成员函数模板都可以接受类型参数 `T`，并在类或成员函数中使用这些参数定义类型。 |
| **成员函数定义位置** | 如果成员函数在类模板内部定义，则无需额外声明模板参数；如果在类模板外部定义，则需要使用模板参数并指定类模板名称。 |
| **模板类型推导（CTAD）** | 在 C++17 中引入的类型推导机制，允许编译器根据构造函数的参数自动推导出模板类型。 |
| **隐式内联**         | 类模板的成员函数模板会被隐式内联，避免了多次定义时的问题。 |
|**常量引用传递**|在模板类的构造函数中，建议通过常量引用来传递参数，以避免不必要的拷贝操作|

### 22.静态成员变量

| 特性                 | 描述                                                         |
|----------------------|--------------------------------------------------------------|
| **共享性**           | 静态成员变量由类的所有实例共享，所有对象对其进行访问时操作的是同一个变量。 |
| **生命周期**         | 静态成员变量在程序开始时创建，在程序结束时销毁，独立于对象的生命周期。 |
| **访问方式**         | 静态成员通常通过类名和域解析符（`::`）访问，也可以通过类的实例访问。 |
| **定义和初始化**     | 静态成员变量必须在类外定义并初始化，常量类型可以在类内初始化。 |
| **优化**             | 静态成员变量适用于跨多个对象共享数据、生成唯一标识符或存储查找表等场景。 |

- 静态成员变量可以使用 `auto` 或类模板参数推断（CTAD）来推导其类型： 在类中，静态成员变量属于类本身，而不是类的某个具体对象，整个程序中只有一份实例。因此，编译器在编译时就能确定静态成员变量的类型，所以可以使用 auto 关键字和 CTAD 来推导其类型。
- 非静态成员变量不能使用这些功能


### 23.静态成员函数

| 特性                           | 静态成员函数                            |
|--------------------------------|---------------------------------------|
| 关联对象                       | 无，属于类本身                           |
| 访问方式                       | 通过类名和`::`操作符直接调用                |
| 是否有`this`指针               | 没有                                    |
| 能否访问非静态成员             | 不能                                    |
| 能否访问静态成员               | 可以                                    |
| 类外定义是否需要`inline`关键字 | 需要（如果定义在类外部时）                  |
| 典型应用场景                   | 单例模式、全局ID生成器、资源管理等            |

- C++不支持静态构造函数
- 当静态成员函数被定义在类内部时，它默认是内联函数
- 当它在类外部定义时，需要显式使用`inline`关键字来指示编译器
- 纯静态类： **不能创建多个实例**：由于所有成员都是静态的，类不能被实例化，也无法创建多个副本。
- 纯静态类：拥有 **全局变量的缺点**
- **命名空间**通常用于存放一组相关的函数和变量，没有访问控制功能。命名空间本质上是为了组织代码而存在的，而静态类则可以拥有访问控制。

static修饰不同变量时：

| 修饰对象 | 作用 | 拷贝副本情况 |
| --- | --- | --- |
| 全局变量 | 改变作用域范围，限制在定义文件内部，具有内部链接属性，其他文件无法直接访问 | 若在头文件中定义，多个源文件包含时，每个源文件有独立副本 |
| 局部变量 | 改变生命周期，在程序运行期间一直存在，但作用域仍在定义的函数或代码块内 | 无多个拷贝副本，始终是同一变量实例 |
| 形参 | 不可用 static 修饰，形参在函数调用时分配内存，修饰无实际意义 | 无 |
| 类（静态嵌套类） | 不依赖外部类对象，可独立创建对象；只能访问外部类静态成员，无外部类对象的 this 指针 | 本身无拷贝副本概念，不同对象是不同实例 |
| 类成员变量 | 类的所有实例对象共享，只有一份内存副本，用于存储类级别信息 | 若在头文件定义，多源文件包含时各有副本；应头文件声明、一个源文件定义初始化以保证唯一副本 |
| 类成员函数 | 属于类本身，可通过类名直接调用；无 this 指针，只能访问静态成员变量和函数 | 无拷贝副本，所有对象共享同一函数代码 | 


### 24.友元非成员函数

- **尽可能避免使用友元函数**：友元函数直接访问类的私有成员，减少了封装性和数据隐藏的优势。因此，应该优先考虑通过公共接口而不是友元函数访问类的数据。
- **使用公共接口**：如果可能，使用公共访问函数而非友元函数。这有助于隔离实现细节，使得修改类实现时对外部代码的影响最小化。
- **慎用多个友元函数**：当有多个友元函数时，类的设计变得复杂。应避免过多地依赖友元函数，以免产生链式的依赖关系。
- 使用友元函数并不违反数据隐藏原则，因为类本身授予友元访问权限。这是类的一种设计选择

### 25.友元类和友元成员函数

| **特性**                | **友元类（Friend Class）**                                  | **友元成员函数（Friend Member Function）**                       |
|---------------------|--------------------------------------------------|------------------------------------------------------|
| **作用**              | 允许整个类访问另一个类的私有成员。                        | 允许特定的成员函数访问另一个类的私有成员。                        |
| **应用场景**           | 当需要多个成员函数访问私有成员时，使用友元类更方便。            | 当只有一个成员函数需要访问私有成员时，使用友元成员函数。             |
| **声明位置**           | 在类的内部使用`friend class`声明。                          | 在类的内部使用`friend`关键字声明特定的成员函数。                   |
| **访问范围**           | 友元类可以访问目标类的所有私有成员。                        | 友元成员函数可以访问目标类的私有成员，但其他成员函数无法访问。         |
| **非对等性**            | 友元关系是单向的，需要显式声明对方为友元。                       | 友元关系是单向的。                                                  |


### 26. 引用限定符

 C++11 引入的引用限定符
1. 引用限定符允许成员函数根据隐式对象（`this` 指针）是左值还是右值来重载，解决返回成员引用时右值对象可能导致的悬空引用问题，提升效率并避免错误。
2. 在成员函数声明中添加 `&` 或 `&&` 实现。`&` 限定函数匹配左值隐式对象，`&&` 限定匹配右值隐式对象。
3. **示例**：

```c++
    // 对左值隐式对象返回常量引用
    const std::string& getName() const & { return m_name; }

    // 对右值隐式对象返回副本
    std::string getName() const && { return m_name; }
    
    //函数参数后面的const主要来声明，该函数是一个常量成员函数：保证函数内不修改成员变量，只能被常量对象调用
    
```

4. **右值处理优化**：对于非常量右值隐式对象，使用 `std::move()` 转移资源，避免不必要的拷贝开销。
5. **工作原理**
  - 左值限定符（`&`）：隐式对象为左值时调用，返回数据成员常量引用，避免拷贝。
  - 右值限定符（`&&`）：隐式对象为右值时调用，返回数据成员副本，避免悬空引用。
6. **注意事项与限制**
  - 左值与右值限定符不能共存。
  - 避免滥用，防止代码难以理解和维护。
  - 标准库中较少使用，因不总能带来显著性能提升。
