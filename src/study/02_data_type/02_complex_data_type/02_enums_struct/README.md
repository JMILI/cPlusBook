# 要点总结

### 1. 用户自定义类型简介


| 类别         | 含义 | 示例 |
|--------------|------|------|
| 基本类型     | C++语言核心类型 | `int`, `std::nullptr_t` |
| 复合类型     | 基本类型的组合 | `int&`, `double*`, `std::string`, `Fraction` |
| 用户定义类型 | 由标准库或实现定义的类类型和枚举类型 | `std::string`, `Fraction` |
| 程序定义类型 | 我们自己定义的类类型和枚举类型 | `Fraction` |


### 2. 非限定作用域枚举


| **特性**           | **非限定作用域枚举**         | **限定作用域枚举**       |
|--------------------|-----------------------------|--------------------------|
| **定义方式**       | 使用`enum`关键字            | 使用`enum class`关键字   |
| **作用域**         | 枚举元素直接在枚举类型定义的作用域中可见 | 枚举元素仅在类型作用域中可见 |
| **命名冲突**       | 易发生命名冲突                | 避免命名冲突            |
| **类型区分**       | 不区分类型                    | 强类型（类型安全）      |

### 3. 非限定作用域枚举的输入与输出

- **枚举元素是整型常量**，可以通过隐式转换为整数。
- **显式赋值**：给枚举元素可能导致枚举元素值相同，从而变得不可区分。
- 使用 `switch` 或者 `operator<<` 来高效打印枚举类型。
- 可以通过 `static_cast` 将整数转换为枚举类型，但无法直接通过整数初始化非限定作用域枚举，除非指定底层类型。
- 可以通过重载 `operator>>` 来允许输入枚举类型。

### 4. 限定作用域枚举（枚举类）

- **不会隐式转换为整数**：这避免了类型之间不应进行比较的情况。
- **枚举元素的作用域限定**：枚举元素仅能在其定义的枚举类型的作用域内使用，不会污染全局命名空间。
- 限定作用域枚举不会隐式转换为整数
- 显式使用`static_cast`可以将枚举类型转换为整数值
- 在C++23中，`std::to_underlying()`被引入作为更简洁的方式来获取枚举的底层整数值
- 如果需要频繁地将限定作用域枚举转换为整数值，可以通过重载运算符来简化这一过程
- 在C++20中，`using enum`语句允许将枚举中的所有元素导入到当前作用域，从而避免冗余的前缀

| 特性 | 非限定作用域枚举 | 限定作用域枚举 |
|------|------------------|----------------|
| 类型安全 | 否 | 是 |
| 隐式转换为整数 | 是 | 否 |
| 枚举元素作用域 | 全局命名空间 | 枚举类型作用域内 |
| 访问方式 | 可以直接使用枚举值名 | 必须通过`EnumType::EnumValue`方式访问 |

### 6. 结构体初始化

- 结构体默认情况下不初始化成员
- 聚合类型：结构体是聚合类型,还有数组，结构体，联合体，类
  - 没有用户声明的构造函数
  - 没有私有或受保护的非静态数据成员
  - 没有虚函数
- 聚合类型：可以使用聚合初始化方式进行初始化，允许提供一个初始化列表
- 初始化列表中成员的数量少于结构体成员的数量，缺失的成员将被**默认初始化**（值初始化）
- `const`结构体**变量和常量表达式（`constexpr`）必须在声明时进行初始化

| 初始化方法 | 示例 | 说明 |
|------------|------|------|
| 聚合初始化 | `Employee joe { 2, 28, 45000.0 };` | 按声明顺序初始化成员 |
| 默认初始化 | `Employee joe {};` | 所有成员被默认值初始化 |
| C++20指定成员初始化 | `Foo f1{ .a{ 1 }, .c{ 3 } };` | 明确指定成员初始化顺序 |
| 将成员赋值 | `joe.age = 33;` | 初始化后单独赋值给成员 |
| 结构体赋值 | `joe = { joe.id, 33, 66000.0 };` | 用新值更新结构体成员 |

### 7. 成员变量的默认初始化

- 对于聚合类型，**首选值初始化**（即使用 `{}`）而不是默认初始化

### 8. 结构体作为函数的输入与输出

- **结构体作为函数参数**：通过结构体传递多个相关变量，比单独传递每个变量更加简洁、易于维护。
- **结构体作为返回值**：结构体允许函数返回多个值，从而避免函数只能返回单一变量的限制。
- **引用传递**：结构体通常通过引用传递，以避免复制成本，尤其是结构体包含较多成员时。
- **返回类型推导与初始化**：结构体可以通过返回类型推导来简化函数声明，使用空大括号进行值初始化确保成员被正确初始化。

### 9. 结构体杂项

1. **结构体嵌套**：可以将结构体作为另一个结构体的成员，增强数据组织和模块化。
2. **数据所有者与查看器**：结构体通常应作为数据的所有者，确保数据成员的生命周期由结构体管理，避免悬空引用。
3. **结构体大小与对齐**：结构体的大小不仅由成员的大小决定，还受到内存对齐和填充的影响。通过优化成员的声明顺序，可以减少填充，从而优化结构体的大小。

### 10. 结构体指针和引用的成员选择操作

- **通过指针访问成员时，始终使用箭头操作符 `->`**，避免手动解引用，简化代码并减少出错的机会。
- **通过引用或对象访问成员时，使用成员选择操作符 `.`**，这符合语法规范。

### 11. 类模板

- **类模板** 可以使你为多种数据类型定义通用的类。
- **模板特化** 提供了对特定类型的定制化处理。
- **多个模板类型参数** 允许你在类中使用不同类型的成员。
- 在多个源文件中使用类模板时，通常将其定义放在头文件中。
- 如果需要更复杂的功能，考虑使用 `std::pair` 或其他标准库类型。

### 12. 类模板参数推导（CTAD）

- CTAD的核心功能是允许编译器从对象初始化的类型推导出模板参数类型
- CTAD在许多情况下是自动生效的，但对于自定义类模板或复杂类型，可能需要提供推导指引
- C++20增强了这项功能，使得编译器能自动为聚合类型生成推导指引，从而进一步简化了代码

### 13. 模板别名 

| **特性**                    | **类型别名**               | **模板别名**                |
|-----------------------------|----------------------------|-----------------------------|
| **定义位置**                 | 局部或全局作用域           | 只能在全局作用域定义        |
| **是否支持CTAD**             | 不支持                     | 支持（C++20及以后）         |
| **使用场景**                 | 简化类型名                 | 简化模板名                  |
| **是否要求显式指定模板类型** | 必须显式指定模板类型        | C++20及以后可以自动推导类型 |
| **作用范围**                 | 局部作用域有效             | 全局作用域有效              |
